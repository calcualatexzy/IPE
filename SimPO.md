# Final plan: reflection-pair SPO pretraining

## 1. Summary and review decisions

Implement reflection-pair generation and an IEPE-style SPO trainer using:

\[
\mathcal L=\mathcal L_{\mathrm{CE}}+\lambda\mathcal L_{\mathrm{SimPO}},
\qquad
\mathcal L_{\mathrm{SimPO}}
=\frac1{N_{\mathrm{pairs}}}\sum_i
-\log\sigma\!\left(\beta(s_i^+-s_i^-)-\gamma\right).
\]

Implementation decisions:

- Write **Parquet output only** in v1; the current training loader cannot consume the proposed JSONL output.
- Omit the story suffix from the negative forward, where it contributes no loss.
- Match existing IPE/EPE/IEPE normalization: separate component means within each local microbatch, with ordinary Trainer gradient accumulation and DDP averaging.
- Use the same post-SFT evaluation workflow as the other methods; no separate pretraining validation pipeline is required.
- Use recorded keyword positions, rather than searching for the first occurrence.
- Preserve checkpoint saving and weight loading; do not promise full optimizer/scheduler resume.
- Include the requested `scripts/pretrain_spo.sh`; omit the additional, unrequested CSCS launcher.

SPO uses ordinary full-model gradients, and unmasked mode retains IEPE’s existing boundary-prediction and position conventions. This document specifies future implementation work; existing trainers retain their current behavior.

## 2. Reflection pairs and preprocessing

### Pair-generation script

Add `add_reflection_pairs.py` with:

```text
--input INPUT_DIRECTORY
--output OUTPUT_DIRECTORY       # optional; defaults to sibling <input>_pairs
--workers N                     # default 1
--limit N                       # optional, for testing
```

Read JSONL, compressed JSONL, or Parquet dataset shards generated by the existing reflection script. Write deterministic, sharded Parquet output. Preserve all original columns and record ordering. Sort source shards and preserve their row order independently of worker completion order. Assign a stable source ID from source-shard identity and row index for preprocessing, diagnostics, and matched controls.

Add:

| Field | Meaning |
|---|---|
| `reflection_positive` | Original reflection, unchanged |
| `reflection_negative` | Same template with preference roles reversed |
| `positive_pref_opp_char_spans` | Positive preference-slot spans |
| `negative_pref_opp_char_spans` | Negative preference-slot spans |
| `has_reflection_pair` | Whether a valid pair exists |

Serialize spans using the existing JSON-string convention.

Recover the original template through exact reconstruction using the recorded keyword and preference values. Render the negative by swapping the `{PREF}` and `{OPP}` arguments. Track preference-slot spans during rendering. Record the recovered template identity. Reject ambiguous reconstructions if they would produce different negatives or scoring spans.

This preserves keyword mentions and correctly handles repeated preferences, single-option templates, and overlapping names. Do not use global string replacement or reuse potentially overinclusive original spans for SPO scoring.

Support both existing template banks and the fixed sentence format produced by `--all-preferences`. For the latter, create one negative reflection in which every preference statement is reversed; do not create a separate training pair per statement in v1. Handle this format explicitly because the current generator leaves scalar `pref_value` and `opp_value` empty. Record the preference-table identity used for reconstruction.

Records without reflections remain available for CE training. Reject unrecognized nonempty reflections, inconsistent metadata, or identical positive/negative outputs with a source-row diagnostic.

Reject overlapping input/output paths and nonempty destinations. Write into a temporary sibling directory and finalize only after successful conversion. Include a small manifest with schema version, source identity, template/preference-table hashes, and conversion counts.

### Paired tokenization

Add a dedicated SPO dataset builder in `ipe/spo_data.py` and a dedicated SPO collator, reusing existing loading, tokenization, and cache utilities. Avoid adding substantial SPO-specific branching to the existing generic collator.

- Require a fast tokenizer and tokenize each story once, obtaining token IDs and offsets together.
- Validate `keyword_position` and `keyword_end_position` against the recorded keyword; map that exact character boundary through tokenizer offsets. If a token crosses the keyword end, insertion starts after that token.
- Sample one insertion point uniformly over eligible token boundaries from keyword end through story end, inclusive. Derive randomness from the experiment seed and stable source ID so worker count and unrelated filtering do not change a sample’s placement.
- Sample during preprocessing, matching existing IEPE. Keep the position fixed across epochs.
- For all-preferences records without a keyword, sample from after the first story token through story end.
- Support an explicit end-of-story placement ablation.

Construct:

```text
Positive: BOS + prefix + <assistant> + R+ + </assistant> + suffix
Negative: BOS + prefix + <assistant> + R- + </assistant>
```

Use BOS only when provided by the tokenizer. Require each framing delimiter to resolve to one distinct special-token ID.

Both branches share exactly the same prefix and insertion point. Store independent reflection boundaries and persona masks because their token lengths can differ. Mark a preference-slot token when its nonempty offset span overlaps a rendered preference-slot character span; document that a boundary token may also contain adjacent template characters. Require at least one scored token on each side for the selected scoring mode, with a source-row error for invalid masks.

Discard the entire paired document from both CE and preference training if either constructed sequence exceeds `seq_len`; never truncate a reflection or silently downgrade an overlength pair to CE-only. Ordinary unpaired stories retain existing truncation behavior. Skip empty stories and report counts. Save retained source IDs so the λ = 0 control uses exactly the same selected documents.

The SPO collator supplies consistently present fields, branch lengths and masks, and an explicit pair-to-source mapping, including mixed and pair-free batches. Right-pad rows to the common length required by the combined forward.

Include dataset content identity, tokenizer configuration and vocabulary identity, pair schema, sequence length, sample limit, delimiters, placement, and seed in the cache fingerprint, plus any option that affects preprocessing. Coordinate cache creation across distributed ranks and publish completed caches atomically.

## 3. Trainer and loss semantics

### Shared IEPE mechanics

Add `ipe/trainer_spo.py` as a sibling trainer. Extract only the reusable attention, position, and prediction-mask helpers from IEPE, with regression tests before extraction. Keep existing IEPE behavior unchanged.

Use the existing tracking mixins and Trainer lifecycle. Avoid copying the entire IEPE trainer or introducing a general trainer framework.

Batch positive/story rows and valid negative rows into one forward. Unpaired stories contribute one row. Keep true branch lengths, but pad all rows to a common length for this dense forward. Omitting the negative suffix removes unnecessary sequence content; it does not guarantee proportional compute savings after padding. Profile this simple implementation before adding separate branch forwards or packing.

Verify custom 4D attention masks and position IDs on the intended Llama attention backend. Use a verified backend and fail clearly for unsupported combinations. Do not assume every attention implementation supports the same custom masks.

### Context cross-entropy

Compute CE on original story targets from positive/story rows only. Exclude reflection tokens, framing-token targets, and padding. Negative rows never contribute context CE.

Default `mask_reflection=true`:

- Suffix tokens cannot attend to either delimiter or reflection content.
- Suffix position IDs retain their original story positions.
- Predict the first suffix token from the last pre-reflection story position.

These rules preserve normal story-only CE conditioning. Verify numerical equivalence of the **CE component and its gradients**, with dropout disabled and identical model parameters, against a plain-story forward. This does not imply that the combined CE + SimPO parameter update leaves story predictions unchanged.

For `mask_reflection=false`, retain the confirmed IEPE convention: the first suffix token still uses the pre-reflection predictor; later suffix predictions may attend to the positive reflection. Preserve IEPE’s suffix position aliasing in this mode too. Document this as partial suffix conditioning.

### Reflection scoring

For each side:

\[
s_i^\pm=
\frac{\sum_t m_{it}^\pm
\log p_\theta(r_{it}^\pm\mid C_i,r_{i,<t}^\pm)}
{\sum_t m_{it}^\pm}.
\]

Here, \(C_i\) is the story prefix plus opening delimiter. Include the first reflection-token prediction; exclude delimiter targets and padding.

Compute teacher-forced token log probabilities and the stable loss:

```text
-logsigmoid(beta * (score_positive - score_negative) - gamma)
```

Normalize each reflection separately, then average valid pair losses within the local microbatch. Do not average token scores across the batch before applying SimPO. There is no extra reflection CE term, frozen model, or reference model.

With `non_template_loss_only=true`, both numerator and denominator use only preference-slot tokens. Template tokens remain part of the conditioning sequence. This restricts scored targets, not all gradient flow through template-token representations. Describe this as a masked SimPO variant. In full-scoring mode, template tokens following a changed preference can have different conditional probabilities; their contributions do not generally cancel.

Use float32 scoring/reduction arithmetic without unnecessarily materializing another full batch-sized vocabulary tensor.

### Microbatch normalization and gradient accumulation

Match the existing normalization convention in `ipe/trainer.py`, `ipe/trainer_ipe.py`, and `ipe/trainer_iepe.py`. Those trainers compute separate context and reflection token means within each microbatch on each rank. SPO keeps the context token mean and replaces the reflection CE mean with a mean of pair losses.

For local microbatch \(b\), define:

\[
\mathcal L_{\mathrm{CE},b}
=\frac{\sum_{t\in\mathrm{story\ targets}}\ell_t}{T_b},
\qquad
\mathcal L_{\mathrm{SimPO},b}
=\frac1{P_b}\sum_{i=1}^{P_b}
-\log\sigma\!\left(\beta(s_i^+-s_i^-)-\gamma\right),
\]

\[
\mathcal L_b=\mathcal L_{\mathrm{CE},b}
+\lambda\mathcal L_{\mathrm{SimPO},b}.
\]

Here, \(T_b\) counts valid story targets in the positive/story rows and \(P_b\) counts valid pairs in that local microbatch. Negative rows never enter \(T_b\). Each reflection score still has its own token denominator before the pair loss is calculated.

- If \(P_b=0\), the preference component is zero and the microbatch contributes CE only. Do not divide by zero or fabricate a pair.
- If \(T_b=0\), the context component is zero. Preserve a graph-connected zero when the whole local loss is zero so backward remains valid, including on pair-free ranks.
- Set `self.model_accepts_loss_kwargs = False`, matching the existing trainers. Leave `compute_loss_func` unset and use the ordinary Trainer `training_step` path for backward, with any existing diagnostic wrapper.
- Do not manually divide the returned loss by accumulation steps, multiply by world size, or all-reduce training denominators. Trainer handles accumulation scaling; DDP handles gradient averaging.
- No custom accumulation-window denominator hook or hook-specific version requirement is needed.

For a full window of \(A\) microbatches on \(W\) DDP ranks, the effective objective is:

\[
\mathcal L_{\mathrm{update}}
=\frac1{WA}\sum_{r=1}^{W}\sum_{b=1}^{A}\mathcal L_{r,b}.
\]

This is an average of local microbatch means, not a global token/pair-weighted mean. Unequal token counts, unequal pair counts, and pair-free microbatches therefore affect weighting exactly according to this convention. Keep valid counts visible in diagnostics. Let Trainer handle partial final accumulation windows and verify that behavior in the tested runtime.

Support single-device training and ordinary DDP in v1. Verify the actual launcher environment and record tested Torch, Transformers, and Accelerate versions. Do not promise compatibility with every version allowed by the repository’s broad dependency lower bounds or with untested distributed backends. Any future move to global normalization should be coordinated across the compared trainers.

### Ablations and diagnostics

- Preserve `full`, `last_k`, and `random_p` reflection attention, with optional BOS visibility. Include the opening delimiter query in reflection-attention restrictions because it predicts the first reflection token. Treat position zero as BOS only when BOS is actually present. Validate `k >= 1` and `0 <= p <= 1`; preserve IEPE’s at-least-one-prefix-position rule for `random_p` when candidates exist, including at `p = 0`.
- For `random_p`, derive the subset from experiment seed, optimizer step, and stable source ID; reuse it for both branches. Use fixed seeds for deterministic diagnostic tests.
- These modes restrict direct attention to prefix positions; they do not erase earlier information already encoded in those positions.
- With λ = 0, skip negative scoring but retain the paired dataset’s selected documents and tokenizer vocabulary. This is a plain-context CE control when reflection masking is enabled. A plain-story forward may bypass both reflection branches in that masked control once CE equivalence is verified; retain the positive reflection when masking is disabled.
- With reflections disabled, use ordinary story preprocessing without requiring pair fields.
- Log CE, SimPO, positive/negative scores, score gap, preference accuracy (`score_positive > score_negative`), margin satisfaction (`beta * gap > gamma`), valid counts, and scored lengths at the configured logging interval. Label these as training diagnostics. Keep component-loss logs aligned with the microbatch-mean objective; aggregate pair score statistics using explicit pair counts. Any logging collectives must run on all ranks at the same schedule, including pair-free ranks, and must not change training loss scaling.
- Monitor both scores separately: a larger gap can result from decreasing negative likelihood without increasing positive likelihood. Report preprocessing filter counts and pair-free microbatch frequency. Fail on invalid metadata/masks and nonfinite training losses.
- Keep existing hidden-state diagnostics on positive/story rows. Slice those rows before aggregation and preferably before copying captured states to CPU so negative rows do not alter their interpretation or inflate tracking cost.

| Setting | Default |
|---|---|
| Trainer type | `spo` |
| λ: `experiment.reflection_loss_weight` | `1.0` |
| `experiment.spo.beta` | `1.0` |
| `experiment.spo.gamma` | `0.0` |

These are initial engineering defaults, not claims of optimal hyperparameters. Validate finite λ ≥ 0, β > 0, and γ ≥ 0. Record γ/β as the target gap in average-log-probability units. Keep learning rate configurable and assess it together with λ and β in pilot runs.

Wire SPO into runtime configuration, special-token registration, dataset selection, and trainer dispatch. Keep ordinary model/checkpoint loading and checkpoint saving. Full Trainer-state resume and conflict-dataset integration are outside v1.

IPE’s frozen-KV, KV-dropout, and separator-only modes remain available through the existing IPE trainer. Reject nondefault IPE-only options for SPO rather than silently ignoring them.

Implement `scripts/pretrain_spo.sh` following the current RunAI launchers:

```text
bash scripts/pretrain_spo.sh [SUFFIX] [DATASET_PATH] [HYDRA_OVERRIDES...]
```

- Preserve server/Conda setup, four-GPU `exec torchrun`, inherited GPU visibility, authentication, cache/output handling, and W&B conventions.

Document generation followed by launcher invocation, including a persona-only example and the existing SFT/evaluation handoff. No additional training library or scheduler launcher is required; record and verify a compatible package combination in the actual launcher environment.

## 5. Evaluation workflow

Use the same downstream workflow as IPE, IEPE, and the other methods:

```text
SPO pretraining checkpoint → existing SFT pipeline → existing evaluation pipeline
```

Use the same SFT configuration, evaluation datasets/prompts, metrics, and checkpoint-selection convention as the compared methods. Save the tokenizer with the pretraining checkpoint, including framing tokens, and verify that the existing SFT/model-loading path reloads it correctly.

No new pretraining validation split, SPO-specific evaluation loop, unseen-template benchmark, or additional post-SFT evaluator is required in v1. Keep pretraining evaluation disabled in the SPO launcher; if enabled accidentally, fail with an actionable message rather than forwarding pair metadata into the model. Training diagnostics and numerical/integration tests remain required, but are not substitutes for the user’s post-SFT evaluation.

## 6. Verification and delivery order

Acceptance checks:

1. **Generation:** every current template, repeated/single-option slots, overlapping names, keyword/value overlap, all-preferences mode, empty reflections, malformed records, and both input formats. Original columns and source files remain unchanged.
2. **Data:** recorded trigger positions, deterministic insertion, matching pair prefixes, independent lengths/masks, mixed batches, length filtering, delimiter validation, and cache separation.
3. **Mathematics:** hand-computed scores and loss; equal scores at γ = 0 produce `log(2)`; increasing the score gap lowers loss; gradients favor positive over negative scores.
4. **Context behavior:** masked CE and its gradients match plain-story training within numerical tolerance; test middle/end insertion and the first suffix target. Verify the agreed unmasked behavior.
5. **Reduction:** distributed and accumulated gradients match an explicit reference that averages local microbatch means, with unequal story lengths and pair counts, pair-free microbatches/ranks, and partial final windows. Verify there is no extra accumulation or world-size scaling. Do not compare against a global token/pair mean when the denominators differ.
6. **Integration:** short training run, persona-only and attention ablations, λ = 0 with identical selected documents, reflections disabled, finite mixed-precision losses, verified attention backend, checkpoint/tokenizer reload, and compatibility with the existing SFT input path. Confirm that accidental pretraining evaluation is rejected clearly. Full downstream SFT and evaluation runs follow the existing experimental workflow and are not implementation acceptance tests.
7. **Regression and launcher:** existing trainer behavior remains unchanged; shell syntax and captured launcher arguments are correct; generated fixture data reaches a successful short SPO training run. Verify tracking excludes negative rows and deterministic preprocessing is independent of conversion worker count.

Implement in order: **pair generator → paired preprocessing/collator → regression-covered shared helpers → SPO loss with existing microbatch normalization → configuration/launcher/docs → integration and SFT-handoff verification**. Establish full-attention masked training first, then complete persona-only scoring and attention/placement ablations before delivery.

Report unavailable GPU or cluster checks explicitly. Do not claim successful distributed training or launcher execution based only on static inspection.
